# Central Enum Registry

> **Status:** Normative. This is the canonical source for all enumerated values in Conductor. All other docs reference this registry. Code implementations MUST match these definitions.

## 1. Run Lifecycle

### 1.1 RunPhase

The phase of a run in its lifecycle. See `RUN_STATE_MACHINE.md` for transition rules.

| Value | Description | Terminal? |
|-------|-------------|-----------|
| `pending` | Run created, awaiting worker pickup | No |
| `planning` | AI agent generating implementation plan | No |
| `awaiting_plan_approval` | Plan ready, awaiting operator approval | No |
| `executing` | AI agent implementing the approved plan | No |
| `awaiting_review` | Implementation complete, PR created, awaiting review | No |
| `blocked` | Run cannot proceed (max retries, errors, rate limits) | No |
| `completed` | Run finished successfully (PR merged) | Yes |
| `cancelled` | Run cancelled by operator or system | Yes |

**Source:** `packages/shared/src/types/index.ts:11`
**Referenced by:** RUN_STATE_MACHINE.md, API_CONTRACTS.md, EVENT_MODEL.md, OBSERVABILITY.md

### 1.2 RunStep

Internal step within a phase. Used by the orchestrator for fine-grained progress tracking.

| Value | Description |
|-------|-------------|
| `setup_worktree` | Creating isolated worktree for the run |
| `route` | Determining which agent to invoke |
| `planner_create_plan` | Planner agent generating implementation plan |
| `reviewer_review_plan` | Reviewer agent evaluating the plan |
| `wait_plan_approval` | Waiting for operator to approve/reject plan |
| `implementer_apply_changes` | Implementer agent writing code |
| `tester_run_tests` | Running tests on implemented changes |
| `reviewer_review_code` | Reviewer agent evaluating code quality |
| `create_pr` | Creating pull request on GitHub |
| `wait_pr_merge` | Waiting for PR to be merged |
| `cleanup` | Cleaning up worktree and resources |

**Source:** `packages/shared/src/types/index.ts:21`

### 1.3 RunStatus

Derived status for UI display. Computed from phase + paused state.

| Value | Description |
|-------|-------------|
| `active` | Run is in a non-terminal, non-blocked phase |
| `paused` | Run is paused by operator |
| `blocked` | Run is in `blocked` phase |
| `finished` | Run is in `completed` or `cancelled` phase |

**Source:** `packages/shared/src/types/index.ts:34`

### 1.4 BlockedReasonCode

Why a run entered the `blocked` phase.

| Value | Description |
|-------|-------------|
| `max_plan_revisions` | Plan revision limit exceeded |
| `max_review_rounds` | Code review round limit exceeded |
| `rate_limit_exhausted` | API rate limits fully consumed |

**Source:** `packages/shared/src/orchestrator/index.ts:52`

## 12. Extension Policy

### 12.1 Adding New Enum Values

1. **Add the value** to the TypeScript union type in its source file
2. **Update this registry** with the new value and description
3. **Update all referencing docs** (check the "Referenced by" field)
4. **Add migration** if the value is stored in the database (e.g., new RunPhase)
5. **Version bump** not required for additive enum changes

### 12.2 Removing Enum Values

1. **Mark as deprecated** in this registry for one minor version
2. **Add migration** to convert existing data to replacement value
3. **Remove** from TypeScript type in the next minor version
4. **Update this registry** and all referencing docs
5. **Version bump** required (minor) for removal

### 12.3 Renaming Enum Values

Treated as **remove old + add new**. Requires migration, version bump, and deprecation period.
